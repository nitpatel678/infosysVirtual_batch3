# Research & Technical Understanding

## 1. LLM Evaluation Workflows

LLM evaluation involves systematically assessing the quality of outputs generated by large language models. Key evaluation approaches include:

- **Human evaluation**: Manual rating of responses for quality, accuracy, and relevance. Gold standard but expensive and slow.
- **Automated metrics**: BLEU, ROUGE, BERTScore for comparing generated text against reference answers.
- **Model-based evaluation (LLM-as-a-Judge)**: Using a separate LLM to evaluate the output of another LLM against defined criteria.

In this project, we use the LLM-as-a-Judge approach where specialized evaluation agents assess AI responses across multiple dimensions.

## 2. Hallucination Detection

AI hallucination occurs when a model generates information that is factually incorrect, fabricated, or not supported by the provided context.

### Types of Hallucination

- **Intrinsic hallucination**: The generated output contradicts the source material.
- **Extrinsic hallucination**: The generated output contains information that cannot be verified from the source material.

### Detection Approaches

- **Reference-based**: Compare the AI response against a known correct answer or source document.
- **Self-consistency**: Generate multiple responses and check for contradictions.
- **Retrieval-augmented verification**: Retrieve relevant documents and check if the response is supported by retrieved evidence.
- **Entailment-based**: Use NLI (Natural Language Inference) models to check if source material entails the claims in the response.

### Key Concepts

- **Factuality**: Whether the response contains accurate, verifiable facts.
- **Faithfulness**: Whether the response is faithful to the provided context/source material (does not add unsupported claims).

## 3. Evaluation Dimensions

Our system evaluates AI responses across four dimensions:

### 3.1 Relevance
Does the AI response actually address the question asked? A response may be factually correct but irrelevant to the specific question.

**Scoring criteria:**
- Does the response directly answer the question?
- Is the information provided pertinent to the query?
- Are there unnecessary or off-topic elements?

### 3.2 Accuracy
Is the information in the AI response factually correct? This is verified against reference answers and retrieved knowledge.

**Scoring criteria:**
- Are the facts stated in the response correct?
- Do the claims match known reference answers?
- Are numerical values, dates, and specific details accurate?

### 3.3 Hallucination
Does the AI response contain fabricated or unsupported information?

**Scoring criteria:**
- Are all claims in the response supported by evidence?
- Does the response contain fabricated facts, names, or events?
- Is the response faithful to the source material (if provided)?

### 3.4 Completeness
Does the AI response provide a thorough answer to the question?

**Scoring criteria:**
- Are all parts of the question addressed?
- Is important information missing?
- Is the level of detail appropriate?

## 4. RAG Architecture

Retrieval-Augmented Generation (RAG) enhances LLM responses by retrieving relevant information from a knowledge base before generating an answer.

### RAG Pipeline

```
User Query
    ↓
Embedding Generation (query → vector)
    ↓
Vector Search (find similar chunks in knowledge base)
    ↓
Retrieved Context (relevant documents/passages)
    ↓
LLM Generation (answer using retrieved context)
```

### Key Components

- **Embeddings**: Dense vector representations of text that capture semantic meaning. We use Sentence Transformers to generate embeddings.
- **Vector Store**: A database optimized for similarity search on high-dimensional vectors. We use FAISS (Facebook AI Similarity Search).
- **Semantic Similarity**: Measuring how similar two pieces of text are based on their vector representations (cosine similarity).
- **Chunking**: Breaking large documents into smaller segments for more precise retrieval.

### RAG in Our System

In our evaluation system, RAG serves a different purpose than typical chatbots. Instead of generating answers, we use RAG to:
1. Retrieve reference knowledge relevant to the user's question.
2. Provide evidence for evaluation agents to assess the AI response.
3. Support accuracy and hallucination detection by comparing claims against retrieved facts.

## 5. LLM-as-a-Judge

The LLM-as-a-Judge paradigm uses a language model to evaluate the output of another language model. This approach is central to our system.

### How It Works

1. Provide the judge LLM with the question, AI response, and evaluation criteria.
2. The judge LLM scores the response on defined dimensions.
3. Multiple judge agents can evaluate different aspects independently.

### Advantages
- Scalable compared to human evaluation.
- Can evaluate nuanced aspects like reasoning quality.
- Consistent when given clear evaluation rubrics.

### Our Agent Design

| Agent | Responsibility |
|-------|---------------|
| Relevance Judge | Assess whether the response addresses the question |
| Accuracy Judge | Verify factual correctness against reference knowledge |
| Hallucination Detection | Identify fabricated or unsupported claims |
| Completeness Judge | Check if the response is thorough and complete |
| Verdict Agent | Aggregate scores and produce final evaluation |

## 6. Evaluation Frameworks

### RAGAS (Retrieval Augmented Generation Assessment)
- Framework for evaluating RAG pipelines.
- Metrics include faithfulness, answer relevancy, context precision, and context recall.
- Provides automated evaluation without requiring human-labeled data.

### TruLens
- Framework for evaluating and tracking LLM applications.
- Supports groundedness, relevance, and toxicity evaluation.
- Provides feedback functions that can be used as evaluation criteria.

### Our Approach
We draw inspiration from these frameworks but implement custom evaluation agents using the LLM-as-a-Judge approach, allowing us to define specific evaluation criteria tailored to our use case.

## 7. Benchmark Datasets

### TruthfulQA
- Dataset of 817 questions designed to test whether language models generate truthful answers.
- Questions span categories including health, law, finance, and politics.
- Each question has a best answer, correct answers, and incorrect answers.
- Useful for testing hallucination detection and factual accuracy.

### SQuAD (Stanford Question Answering Dataset)
- Large-scale reading comprehension dataset.
- Contains 100,000+ question-answer pairs based on Wikipedia articles.
- Each question has a context paragraph and an answer extracted from that context.
- Useful for testing retrieval quality and accuracy evaluation.

Both datasets are available on Hugging Face and will be used to build our reference knowledge base.

## 8. Scoring Approach

### Scoring Scale
Each evaluation dimension is scored on a scale of **1 to 5**:

| Score | Meaning |
|-------|---------|
| 1 | Very Poor — Major issues detected |
| 2 | Poor — Significant problems |
| 3 | Acceptable — Some issues but mostly adequate |
| 4 | Good — Minor issues only |
| 5 | Excellent — No issues detected |

### Final Verdict
The Verdict Agent produces a final evaluation by:
1. Collecting scores from all four evaluation agents.
2. Considering the reasoning provided by each agent.
3. Producing an overall assessment with confidence level.

### Output Structure
Each evaluation produces:
- Individual dimension scores (1-5) with reasoning.
- Supporting evidence from the knowledge base.
- Overall verdict (Reliable / Partially Reliable / Unreliable).
- Confidence level.
